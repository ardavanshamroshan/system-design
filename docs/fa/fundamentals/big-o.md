## چیست و چرا

**Big O** رشد تقریبی هزینهٔ Algorithm (زمان یا حافظه) را نسبت به اندازهٔ ورودی `n` توصیف می‌کند — نه میلی‌ثانیه روی لپ‌تاپ تو.

| نگاه | سؤال |
|------|------|
| زمان مطلق | «روی مک من چند ms؟» |
| Big O | «اگر `n` ده برابر شود، هزینه تقریباً چند برابر؟» |

در مصاحبه و طراحی سیستم زبان مشترک است: «با ۱۰× ترافیک، CPU/DB/هزینه چند برابر می‌شود؟»

ساده برای حذف ترم‌های اضافه:

1. فقط بالاترین Order را نگه دار  
2. ثابت جلوی آن را بینداز  

```
f(n) = 3n² + 2n + 1000 log n + 5000  →  O(n²)
```

---

## تعریف عملی

`f(n) = O(g(n))` یعنی برای `n`های به اندازهٔ کافی بزرگ، یک ثابت `c` وجود دارد که:

```
|f(n)| ≤ c · g(n)
```

یعنی: `f` **سریع‌تر از** `c·g` رشد نمی‌کند (Upper Bound).  
دقیق‌ترین Bound تنگ‌تر را ترجیح بده: `O(n³)` درست است ولی برای `73n³+…` معمولاً `O(n³)` یا بهتر `Θ(n³)` می‌گویی.

علامت `=` در Big O عرفاً «عضویت در مجموعه» است — یک‌طرفه: از `n = O(n²)` نتیجه نمی‌گیری `n² = O(n)`.

## خانوادهٔ نمادها (O, Θ, Ω)

| نماد | معنی در CS | شهود |
|------|------------|------|
| **O** | Upper Bound | «بدتر از این نمی‌شود» (تا ثابت) |
| **Ω** (Knuth) | Lower Bound | «حداقل این‌قدر» |
| **Θ** | Tight Bound | هم بالا هم پایین — همان Order |
| **o** (little-o) | اکیداً کندتر | `f/g → 0` |
| **ω** | اکیداً سریع‌تر | `f/g → ∞` |

مثال: `2n² − 10n = Θ(n²)` برای `n` بزرگ.  
در گفت‌وگوی روزمره اغلب همه چیز را «Big O» می‌گویند حتی وقتی منظور Θ است.

مراتب رشد (تقریبی، خوب → بد برای زمان):

```
O(1) < O(log n) < O(√n) < O(n) < O(n log n) < O(n²) < O(2ⁿ) < O(n!)
```

قواعد مفید:

- توان بزرگ بر توان کوچک غالب است: `n² = O(n³)`  
- توان بر لگاریتم غالب است: `(log n)¹⁰⁰ = O(n)`  
- نمایی بر چندجمله‌ای غالب است: `n¹⁰⁰ = O(2ⁿ)`  
- پایهٔ لگاریتم مهم نیست: `O(log₂ n) = O(log₁₀ n)`  
- پایهٔ نمایی مهم است: `2ⁿ` و `3ⁿ` هم‌مرتبه نیستند  

---

## مراتب رایج

| نماد | نام | مثال Algorithm / کار |
|------|-----|---------------------|
| **O(1)** | ثابت | hash lookup، دسترسی Array با Index، `pop` از ته stack |
| **O(log n)** | لگاریتمی | Binary search، Height Balanced BST، B-Tree |
| **O(n)** | خطی | یک اسکن، پیدا کردن max در Array نامرتب |
| **O(n log n)** | linearithmic | Merge sort، heap sort، Average quicksort، بسیاری از sortهای زبان |
| **O(n²)** | درجه دو | Bubble/selection/insertion ساده، بعضی ماتریس‌های کوچک |
| **O(n³)** | مکعبی | ضرب ماتریس naive |
| **O(2ⁿ)** | نمایی | همهٔ Subsetها، بعضی recursionهای شاخه‌دار (فیبوناچی خام) |
| **O(n!)** | فاکتوریل | همهٔ Permutationها، TSP brute force |

وقتی دو ورودی داری: تو در تو روی `n` و `m` → **O(n·m)** نه لزوماً `O(n²)`.

## چطور از روی کد بخوانیم

| Pattern | Complexity تقریبی |
|------|----------------|
| بدون حلقه وابسته به `n` | O(1) |
| یک حلقه روی `n` | O(n) |
| هر گام نصف کردن بازه | O(log n) |
| حلقه + نصف‌کردن Recursive (مثل merge sort) | O(n log n) |
| دو حلقه تو در تو روی همان `n` | O(n²) |
| recursion دو شاخه بدون memo | اغلب O(2ⁿ) |

ثابت‌ها را ساده کن: `O(2n)` و `O(100n)` هر دو **O(n)** هستند — شکل رشد مهم است، نه ضریب.

## مثال PHP / Python

### O(1)

```php
return $arr[0];
```

```python
return arr[0]
```

### O(n)

```php
function findMax(array $arr): mixed {
    $max = $arr[0];
    foreach ($arr as $x) {
        if ($x > $max) $max = $x;
    }
    return $max;
}
```

### O(log n) — binary search

```python
def binary_search(arr, target):
    lo, hi = 0, len(arr) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if arr[mid] == target:
            return mid
        if arr[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1
```

### O(n²)

```php
for ($i = 0; $i < $n; $i++) {
    for ($j = 0; $j < $n; $j++) { /* ... */ }
}
```

### O(n) زمان + O(n) حافظه — trade-off

```php
function hasDuplicate(array $ids): bool {
    $seen = [];
    foreach ($ids as $id) {
        if (isset($seen[$id])) return true;
        $seen[$id] = true;
    }
    return false;
}
```

به‌جای مقایسهٔ جفتی O(n²).

### O(2ⁿ) — Subsetها (مفهومی)

```python
# 2^n زیرمجموعه برای n عنصر
for mask in range(1 << n):
    ...
```

## نکات و Anti-pattern {#نکات-و-ضدالگو}

1. **Worst case** معمولاً منظور است مگر بگویی average/amortized.  
2. **زمان ≠ حافظه** — می‌توانی یکی را با دیگری عوض کنی.  
3. **I/O** اغلب از CPU گران‌تر است: N+1 query = O(n) round-trip شبکه.  
4. micro-optimize حلقه وقتی Algorithm O(n²) است → اولویت غلط.  
5. «روی ۱۰ رکورد سریع» ≠ «روی ۱۰ میلیون هم سریع».  
6. Average hash O(1) است؛ worst case (collision عمدی) می‌تواند O(n) باشد.

## پرسش و پاسخ {#qa}

### س۱ — تعریف رسمی Big O چیست؟ نشان بده `3n² + 2n + 1000 log n + 5000 = O(n²)`. <Badge type="danger" text="حیاتی" /> {#q-1}

::: details پاسخ {open}
**پاسخ:** `f(n) = O(g(n))` یعنی ثابت‌های مثبت `c` و `n₀` **وجود دارند** که برای هر `n ≥ n₀` داشته باشیم `f(n) ≤ c·g(n)`. کافی است یک جفت `c` و `n₀` پیدا کنی؛ لازم نیست کوچک‌ترینشان باشد.

اثبات: برای `n ≥ 1` داریم `log n ≤ n ≤ n²` و `1 ≤ n²`. پس:

```text
3n² + 2n + 1000 log n + 5000  ≤  3n² + 2n² + 1000n² + 5000n²  =  6005 n²
=> c = 6005, n0 = 1
```

**مثال واقعی:** `n₀` همان «برای `n` به اندازهٔ کافی بزرگ» است. جملهٔ `5000` (هزینهٔ ثابت راه‌اندازی، مثل باز کردن connection) برای `n = 10` غالب است و برای `n = 10⁶` دیده نمی‌شود؛ برای همین روی دادهٔ کوچک، هزینهٔ ثابت را اندازه می‌گیری نه Algorithm را.

<strong class="qa-trap">دام مصاحبه:</strong> فکر کنی `c` باید ۱ یا عددی کوچک باشد. تعریف فقط *وجود* یک ثابت را می‌خواهد؛ `c = 6005` کاملاً معتبر است، و دقیقاً به همین دلیل Big O دربارهٔ سرعت مطلق چیزی نمی‌گوید.
:::

### س۲ — اگر `O(n¹⁰⁰)` هم برای یک Algorithm خطی «درست» است، چرا نمی‌گوییم؟ Tight Bound یعنی چه؟ <Badge type="warning" text="مهم" /> {#q-2}

::: details پاسخ {open}
**پاسخ:** Big O فقط Upper Bound است، پس هر تابع بزرگ‌تری هم Upper Bound معتبر است: Algorithm خطی `O(n)`، `O(n²)` و `O(2ⁿ)` هم هست. ولی Bound غیرتنگ اطلاعاتی نمی‌دهد. Tight Bound (`Θ`) یعنی همان تابع هم Upper Bound و هم Lower Bound است؛ در عمل همیشه **کوچک‌ترین** Upper Boundی را که می‌توانی ثابت کنی بگو.

**مثال واقعی:** «این Query حداکثر یک ساعت طول می‌کشد» دربارهٔ Query ۳ میلی‌ثانیه‌ای درست است ولی برای برنامه‌ریزی ظرفیت بی‌ارزش. Bound `O(n²)` برای کدی که واقعاً `O(n log n)` است یعنی برآورد ۵۰ هزار برابر بدبینانه در `n = 10⁶`.

**یوزکیس:** وقتی تحلیل دقیق سخت است، Upper Bound شل را بگو ولی صریحاً اعلام کن که تنگ نیست: «حداکثر `O(n²)` است؛ احتمالاً بهتر، ولی ثابتش نکرده‌ام».

<strong class="qa-trap">دام مصاحبه:</strong> مصاحبه‌گر می‌پرسد «binary search برابر `O(n)` است؟». جواب درست: «از نظر تعریف بله، ولی Tight Boundش `Θ(log n)` است».
:::

### س۳ — `2ⁿ⁺¹ = O(2ⁿ)` درست است؟ `2²ⁿ = O(2ⁿ)` چطور؟ چرا پایهٔ لگاریتم مهم نیست ولی پایهٔ نمایی مهم است؟ <Badge type="warning" text="مهم" /> {#q-3}

::: details پاسخ {open}
**پاسخ:** `2ⁿ⁺¹ = 2·2ⁿ` است، یعنی فقط یک ضریب ثابت: بله، `O(2ⁿ)`. ولی `2²ⁿ = 4ⁿ = 2ⁿ·2ⁿ`؛ نسبتش به `2ⁿ` خودِ `2ⁿ` است که به بی‌نهایت می‌رود: نه. قاعده: ثابتی که **با نما جمع** می‌شود ضریب ثابت است؛ ثابتی که **در نما ضرب** می‌شود Order را عوض می‌کند. تغییر پایهٔ لگاریتم یک ضریب ثابت بیرونی است (`log₂ n = 3.32·log₁₀ n`)؛ تغییر پایهٔ نمایی معادل ضرب نما در یک ثابت است (`3ⁿ = 2^(1.585n)`).

**مثال واقعی:** backtracking با ضریب انشعاب ۲ در برابر ۳ برای `n = 30`: حدود ۱۰⁹ حالت (یک ثانیه) در برابر حدود ۲×۱۰¹⁴ حالت (بیش از دو روز). برای همین Prune کردن حتی یک شاخه در هر سطح، مسئلهٔ نشدنی را شدنی می‌کند.

<strong class="qa-trap">دام مصاحبه:</strong> ساده‌کردن `O(2²ⁿ)` یا `O(3ⁿ)` به `O(2ⁿ)` به بهانهٔ «ثابت‌ها را دور می‌ریزیم».
:::

### س۴ — کی باید `O(n + m)` یا `O(n·m)` بگوییم و کی مجازیم به `O(n)` یا `O(n²)` ساده کنیم؟ <Badge type="danger" text="حیاتی" /> {#q-4}

::: details پاسخ {open}
**پاسخ:** هر ورودی مستقل متغیر خودش را می‌خواهد. دو حلقهٔ **پشت‌سرهم** روی دو ورودی `O(n + m)` است و دو حلقهٔ **تو در تو** `O(n·m)`. فقط وقتی می‌توانی ساده کنی که رابطهٔ دو متغیر را بدانی: اگر `m ≤ n` آن‌وقت `O(n + m) = O(n)`؛ اگر `m ≈ n` آن‌وقت `O(n·m) = O(n²)`.

| وضعیت | Complexity |
| --- | --- |
| `n` سفارش، `m` کاربر مسدود، `in_array` در حلقه | `O(n·m)` |
| همان با `array_flip` + `isset` | `O(n + m)` |
| `n` String با طول میانگین `k`، مقایسهٔ جفتی | `O(n²·k)` |

**مثال واقعی:** join دو جدول با ۱۰ میلیون و ۱۰۰ ردیف: `O(n·m)` یعنی ۱۰⁹ عمل که قابل‌قبول است. اگر هر دو را `n` بنامی و بگویی `O(n²)`، به‌نظر می‌رسد ۱۰¹⁴ عمل لازم است و تصمیم غلط می‌گیری.

<strong class="qa-trap">دام مصاحبه:</strong> دو حلقهٔ تو در تو روی دو Array متفاوت را بدون فکر `O(n²)` بگویی. اول بپرس اندازه‌ها چه نسبتی دارند.
:::

### س۵ — little-o با Big O چه فرقی دارد و کجا به کار می‌آید؟ <Badge type="info" text="تکمیلی" /> {#q-5}

::: details پاسخ {open}
**پاسخ:** `f = O(g)` یعنی `f` حداکثر هم‌مرتبهٔ `g` است (مثل ≤). `f = o(g)` یعنی `f` **اکیداً** کندتر رشد می‌کند (مثل علامت «کوچک‌تر اکید»): نسبت `f/g` به صفر میل می‌کند. پس `n = O(n)` درست است ولی `n = o(n)` غلط؛ `n = o(n²)` و `log n = o(n)` درست‌اند. `ω` قرینهٔ آن برای Lower Bound اکید است.

**مثال واقعی:** جمله‌هایی مثل «overhead این Index `o(n)` است» یعنی سهم overhead با بزرگ‌شدن داده به صفر میل می‌کند. یا در ساختارهای succinct: فضای اضافی `o(n)` بیت.

**یوزکیس:** در کار روزمره به‌ندرت؛ بیشتر در مقاله‌ها و مستندات Data Structure دیده می‌شود.

<strong class="qa-trap">دام مصاحبه:</strong> `o` را «Big O دقیق‌تر» یا مترادف `Θ` بدانی. `Θ` یعنی هم‌مرتبه؛ `o` یعنی اکیداً کوچک‌تر. این دو با هم ناسازگارند.
:::

### س۶ — این تابع‌ها را از کندترین رشد به سریع‌ترین مرتب کن: `n log n`، `n^1.5`، `(log n)³`، `√n`، `2^(log₂ n)`، `n!`، `2ⁿ`، `n^0.01`. <Badge type="warning" text="مهم" /> {#q-6}

::: details پاسخ {open}
**پاسخ:**

```text
(log n)^3  <  n^0.01  <  sqrt(n)  <  2^(log2 n) = n  <  n log n  <  n^1.5  <  2^n  <  n!
```

قاعده‌های به‌کاررفته: هر توان مثبت `n` (حتی `n^0.01`) در نهایت از هر توان لگاریتم بزرگ‌تر می‌شود؛ `2^(log₂ n)` دقیقاً برابر `n` است؛ `n log n` از `n^1.5` کوچک‌تر است چون `log n` از `√n` کوچک‌تر است؛ فاکتوریل از هر نمایی با پایهٔ ثابت بزرگ‌تر است.

**مثال واقعی:** «در نهایت» می‌تواند خیلی دور باشد: `n^0.01` فقط برای `n`های بزرگ‌تر از حدود ۱۰¹⁰⁰⁰ از `(log₂ n)³` جلو می‌زند. برای هر `n` واقعی، Algorithm `(log n)³` کندتر از `n^0.01` است. Asymptotic بودن Big O را جدی بگیر.

<strong class="qa-trap">دام مصاحبه:</strong> `2^(log₂ n)` را نمایی حساب کنی. قبل از مقایسه، عبارت‌ها را ساده کن.
:::

### س۷ — قواعد جمع و ضرب Big O چیست و علامت `=` چه مشکلی می‌سازد؟ <Badge type="warning" text="مهم" /> {#q-7}

::: details پاسخ {open}
**پاسخ:**

| قاعده | مثال |
| --- | --- |
| جمع: `O(f) + O(g) = O(max(f, g))` | اعتبارسنجی `O(n)` + Sort `O(n log n)` + حذف تکراری `O(n)` = `O(n log n)` |
| ضرب: `O(f) · O(g) = O(f·g)` | حلقهٔ `n`تایی با بدنهٔ `O(log n)` = `O(n log n)` |
| ضریب ثابت: `c · O(f) = O(f)` | سه pass روی داده هنوز `O(n)` است |

علامت `=` این‌جا «عضو مجموعه است» معنی می‌دهد و یک‌طرفه است: `n = O(n²)` درست است ولی `O(n²) = n` بی‌معناست؛ و از `n = O(n²)` و `n² = O(n²)` نتیجه نمی‌شود `n = n²`.

**مثال واقعی:** در یک pipeline چندمرحله‌ای، Asymptotic Bottleneck همان مرحله‌ای است که بالاترین Order را دارد؛ بهینه‌کردن مرحله‌های دیگر Order کل را عوض نمی‌کند (ولی ممکن است ثابت را عوض کند).

<strong class="qa-trap">دام مصاحبه:</strong> قاعدهٔ جمع فقط برای تعداد **ثابتی** از جمله‌ها درست است. `O(n) + O(n) + … + O(n)` اگر `n` بار تکرار شود `O(n²)` است، نه `O(n)`.
:::

### س۸ — `n` دقیقاً چیست؟ چرا آزمون اول‌بودن با `O(√N)` در واقع نمایی است؟ <Badge type="info" text="تکمیلی" /> {#q-8}

::: details پاسخ {open}
**پاسخ:** در تعریف دقیق، `n` **اندازهٔ ورودی** است (تعداد بیت یا تعداد عنصر)، نه *مقدار* عددی آن. عدد `N` با `b = log₂ N` بیت نوشته می‌شود؛ حلقه تا `√N` یعنی `2^(b/2)` گام: نمایی بر حسب طول ورودی. به چنین Algorithmی **pseudo-polynomial** می‌گویند: بر حسب مقدار عددی چندجمله‌ای، بر حسب طول ورودی نمایی.

**مثال واقعی:** knapsack با DP برابر `O(n·W)` است. اگر ظرفیت `W` به ریال باشد و ۱۰⁹، جدول DP یک میلیارد ستون دارد، با اینکه `W` فقط ۳۰ بیت ورودی است. امنیت RSA هم روی همین تفاوت بنا شده: تجزیهٔ عدد ۲۰۴۸ بیتی با تقسیم آزمایشی حدود `2¹⁰²⁴` گام می‌خواهد.

**یوزکیس:** همیشه مشخص کن `n` چیست: تعداد ردیف؟ طول String؟ مقدار عدد؟ مجموع اندازهٔ payloadها؟

<strong class="qa-trap">دام مصاحبه:</strong> ادعای «knapsack را در زمان چندجمله‌ای حل کردم پس P = NP». `O(n·W)` بر حسب اندازهٔ ورودی چندجمله‌ای نیست.
:::

### س۹ — ترافیک یا داده ۱۰ برابر می‌شود. با Big O چه برآوردی می‌کنی و چطور Order یک کد را تجربی تشخیص می‌دهی؟ <Badge type="danger" text="حیاتی" /> {#q-9}

::: details پاسخ {open}
**پاسخ:** Big O مستقیماً ضریب رشد هزینه را می‌دهد. برای تشخیص تجربی، **آزمون دو برابر کردن** را انجام بده: زمان را برای `n` و `2n` اندازه بگیر و نسبت را ببین.

| Order | `n` ده برابر شود | نسبت `T(2n) / T(n)` |
| --- | --- | --- |
| `O(1)` | بدون تغییر | ۱ |
| `O(log n)` | چند گام بیشتر | کمی بیش از ۱ |
| `O(n)` | ۱۰ برابر | ۲ |
| `O(n log n)` | حدود ۱۲ برابر | کمی بیش از ۲ |
| `O(n²)` | ۱۰۰ برابر | ۴ |
| `O(n³)` | ۱۰۰۰ برابر | ۸ |
| `O(2ⁿ)` | به توان ۱۰ | مربع زمان قبلی |

**مثال واقعی:** job شبانه‌ای که با ۱۰۰ هزار ردیف ۲ دقیقه طول می‌کشد و با ۲۰۰ هزار ردیف ۸ دقیقه: نسبت ۴ یعنی `O(n²)`. با یک میلیون ردیف ۲۰۰ دقیقه خواهد شد و از پنجرهٔ شبانه بیرون می‌زند؛ این را قبل از رسیدن داده به آن اندازه می‌فهمی.

**یوزکیس:** برنامه‌ریزی ظرفیت: مسیرهای `O(n)` با اضافه‌کردن Server مقیاس می‌گیرند؛ مسیر `O(n²)` با ۱۰ برابر داده ۱۰۰ برابر منبع می‌خواهد و باید Algorithmش عوض شود.

<strong class="qa-trap">دام مصاحبه:</strong> اندازه‌گیری روی `n` خیلی کوچک. آن‌جا هزینه‌های ثابت (راه‌اندازی، cache، JIT) غالب‌اند و نسبت‌ها گمراه‌کننده می‌شوند؛ چند نقطه با `n` بزرگ بگیر.
:::
