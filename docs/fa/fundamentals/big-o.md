## چیست و چرا

**Big O** رشد تقریبی هزینهٔ الگوریتم (زمان یا حافظه) را نسبت به اندازهٔ ورودی `n` توصیف می‌کند — نه میلی‌ثانیه روی لپ‌تاپ تو.

| نگاه | سؤال |
|------|------|
| زمان مطلق | «روی مک من چند ms؟» |
| Big O | «اگر `n` ده برابر شود، هزینه تقریباً چند برابر؟» |

در مصاحبه و طراحی سیستم زبان مشترک است: «با ۱۰× ترافیک، CPU/DB/هزینه چند برابر می‌شود؟»

ساده برای حذف ترم‌های اضافه:

1. فقط بالاترین مرتبه را نگه دار  
2. ثابت جلوی آن را بینداز  

```
f(n) = 3n² + 2n + 1000 log n + 5000  →  O(n²)
```

## تعریف عملی

`f(n) = O(g(n))` یعنی برای `n`های به اندازهٔ کافی بزرگ، یک ثابت `c` وجود دارد که:

```
|f(n)| ≤ c · g(n)
```

یعنی: `f` **سریع‌تر از** `c·g` رشد نمی‌کند (کران بالا).  
دقیق‌ترین کران تنگ‌تر را ترجیح بده: `O(n³)` درست است ولی برای `73n³+…` معمولاً `O(n³)` یا بهتر `Θ(n³)` می‌گویی.

علامت `=` در Big O عرفاً «عضویت در مجموعه» است — یک‌طرفه: از `n = O(n²)` نتیجه نمی‌گیری `n² = O(n)`.

## خانوادهٔ نمادها (O, Θ, Ω)

| نماد | معنی در CS | شهود |
|------|------------|------|
| **O** | کران بالا | «بدتر از این نمی‌شود» (تا ثابت) |
| **Ω** (Knuth) | کران پایین | «حداقل این‌قدر» |
| **Θ** | کران تنگ | هم بالا هم پایین — همان مرتبه |
| **o** (little-o) | اکیداً کندتر | `f/g → 0` |
| **ω** | اکیداً سریع‌تر | `f/g → ∞` |

مثال: `2n² − 10n = Θ(n²)` برای `n` بزرگ.  
در گفت‌وگوی روزمره اغلب همه چیز را «Big O» می‌گویند حتی وقتی منظور Θ است.

مراتب رشد (تقریبی، خوب → بد برای زمان):

```
O(1) < O(log n) < O(√n) < O(n) < O(n log n) < O(n²) < O(2ⁿ) < O(n!)
```

قواعد مفید:

- توان بزرگ بر توان کوچک غالب است: `n² = O(n³)`  
- توان بر لگاریتم غالب است: `(log n)¹⁰⁰ = O(n)`  
- نمایی بر چندجمله‌ای غالب است: `n¹⁰⁰ = O(2ⁿ)`  
- پایهٔ لگاریتم مهم نیست: `O(log₂ n) = O(log₁₀ n)`  
- پایهٔ نمایی مهم است: `2ⁿ` و `3ⁿ` هم‌مرتبه نیستند  

---

## مراتب رایج

| نماد | نام | مثال الگوریتم / کار |
|------|-----|---------------------|
| **O(1)** | ثابت | hash lookup، دسترسی آرایه با ایندکس، `pop` از ته stack |
| **O(log n)** | لگاریتمی | Binary search، ارتفاع BST متوازن، B-Tree |
| **O(n)** | خطی | یک اسکن، پیدا کردن max در آرایهٔ نامرتب |
| **O(n log n)** | linearithmic | Merge sort، heap sort، متوسط quicksort، بسیاری از sortهای زبان |
| **O(n²)** | درجه دو | Bubble/selection/insertion ساده، بعضی ماتریس‌های کوچک |
| **O(n³)** | مکعبی | ضرب ماتریس naive |
| **O(2ⁿ)** | نمایی | همهٔ زیرمجموعه‌ها، بعضی recursionهای شاخه‌دار (فیبوناچی خام) |
| **O(n!)** | فاکتوریل | همهٔ جایگشت‌ها، TSP brute force |

وقتی دو ورودی داری: تو در تو روی `n` و `m` → **O(n·m)** نه لزوماً `O(n²)`.

## چطور از روی کد بخوانیم

| الگو | پیچیدگی تقریبی |
|------|----------------|
| بدون حلقه وابسته به `n` | O(1) |
| یک حلقه روی `n` | O(n) |
| هر گام نصف کردن بازه | O(log n) |
| حلقه + نصف‌کردن بازگشتی (مثل merge sort) | O(n log n) |
| دو حلقه تو در تو روی همان `n` | O(n²) |
| recursion دو شاخه بدون memo | اغلب O(2ⁿ) |

ثابت‌ها را ساده کن: `O(2n)` و `O(100n)` هر دو **O(n)** هستند — شکل رشد مهم است، نه ضریب.

## مثال PHP / Python

### O(1)

```php
return $arr[0];
```

```python
return arr[0]
```

### O(n)

```php
function findMax(array $arr): mixed {
    $max = $arr[0];
    foreach ($arr as $x) {
        if ($x > $max) $max = $x;
    }
    return $max;
}
```

### O(log n) — binary search

```python
def binary_search(arr, target):
    lo, hi = 0, len(arr) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if arr[mid] == target:
            return mid
        if arr[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1
```

### O(n²)

```php
for ($i = 0; $i < $n; $i++) {
    for ($j = 0; $j < $n; $j++) { /* ... */ }
}
```

### O(n) زمان + O(n) حافظه — trade-off

```php
function hasDuplicate(array $ids): bool {
    $seen = [];
    foreach ($ids as $id) {
        if (isset($seen[$id])) return true;
        $seen[$id] = true;
    }
    return false;
}
```

به‌جای مقایسهٔ جفتی O(n²).

### O(2ⁿ) — زیرمجموعه‌ها (مفهومی)

```python
# 2^n زیرمجموعه برای n عنصر
for mask in range(1 << n):
    ...
```

## نکات و ضدالگو

1. **Worst case** معمولاً منظور است مگر بگویی average/amortized.  
2. **زمان ≠ حافظه** — می‌توانی یکی را با دیگری عوض کنی.  
3. **I/O** اغلب از CPU گران‌تر است: N+1 query = O(n) round-trip شبکه.  
4. micro-optimize حلقه وقتی الگوریتم O(n²) است → اولویت غلط.  
5. «روی ۱۰ رکورد سریع» ≠ «روی ۱۰ میلیون هم سریع».  
6. Average hash O(1) است؛ worst case (collision عمدی) می‌تواند O(n) باشد.

## قاعدهٔ تصمیم

1. اول پیچیدگی الگوریتم + I/O را ببین.  
2. بعد اگر لازم بود micro-optimize کن.  
3. برای مقایسهٔ گزینه‌ها از جدول مراتب استفاده کن؛ برای SLA واقعی ثابت‌ها و اندازه‌گیری را هم ببین.
