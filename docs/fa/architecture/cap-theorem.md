# قضیهٔ CAP

## گزارهٔ اصلی

در یک **سیستم توزیع‌شده**، وقتی partition رخ دهد، هر سه تا را ۱۰۰٪ نمی‌توانی داشته باشی:

| حرف | معنی |
|-----|------|
| **C** Consistency | هر node همان دادهٔ به‌روز را می‌بیند |
| **A** Availability | هر request بدون شکست پاسخی می‌گیرد |
| **P** Partition tolerance | سیستم با وجود قطع شبکه کار می‌کند |

در عمل شبکه fail می‌شود → **P تقریباً اجباری است**. انتخاب واقعی معمولاً بین **CP** و **AP** است.

---

## مدل ذهنی

دو دیتاسنتر؛ لینک بینشان قطع است (partition):

```
[Node A]  ⚡ cut  [Node B]
 Users still hit both
```

- فقط وقتی nodeها sync هستند جواب بده → **Consistency** را نگه دار، Availability را قربانی کن (**CP**).  
- هر node از دادهٔ محلی جواب بدهد → **Availability** را نگه دار؛ جواب‌ها ممکن است واگرا شوند (**AP**).

---

## مثال‌های تقریبی

| سیستم | تمایل رایج | یادداشت کوتاه |
|-------|------------|---------------|
| PostgreSQL primary + sync replica | نزدیک به CP | روی partition ممکن است write متوقف شود |
| Cassandra / سبک Dynamo | نزدیک به AP | write را می‌پذیرد؛ بعداً reconcile می‌کند |
| ZooKeeper / etcd | CP | هماهنگی؛ بدون quorum → بدون جواب |
| Redis Cluster | وابسته به config | ساده نگیر — مستندات را بخوان |

::: warning
برچسب‌های CAP در صفحات بازاریابی شلخته‌اند؛ quorum، replication و رفتار کلاینت را چک کن.
:::

---

## Consistency یک طیف است

CAP با «strong در برابر eventual consistency» قاطی می‌شود، اما یکی نیستند:

- **Strong:** بعد از write موفق، هر read آن را می‌بیند.  
- **Eventual:** اگر writeها متوقف شوند، replicaها هم‌گرا می‌شوند.  
- **Read-your-writes / Causal:** تضمین‌های میانی برای UX بهتر.

---

## در طراحی چه بپرسی

1. اگر دو کاربر موجودی کیف پول متفاوت ببینند، قابل قبول است؟  
2. اگر checkout ۳۰ ثانیه down باشد، کسب‌وکار می‌میرد؟  
3. احتمال partition چقدر است (یک DC در برابر multi-region)؟

| ترجیح بیزنس | انتخاب تقریبی |
|-------------|---------------|
| پول، موجودی، رزرو صندلی | تمایل به CP / strong consistency |
| لایک، فید، شمارندهٔ تقریبی | تمایل به AP / eventual |
| کانفیگ توزیع‌شده | معمولاً CP |

---

## قاعدهٔ تصمیم

1. اول بفهم **دادهٔ غلط** یعنی چه، بعد ابزار انتخاب کن.  
2. «هم C هم A می‌خواهیم» بدون تعریف partition → بازاریابی است.  
3. خیلی سیستم‌ها در happy path شبیه CA به‌نظر می‌رسند؛ آزمون واقعی partition است.
